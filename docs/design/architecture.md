# itadict — Shell, Data and Offline Architecture

Four runtime layers: the shell, the router, the data client, and the screens. Read `README.md` first
for the purpose and the frozen decisions. `docs/adr/` holds the decisions this file obeys. This file
is the mechanics, and it follows the code on disk.

## Layout

```
index.html              one module script, one #app node, every URL relative
styles.css              all CSS: shell, tab bar, rows, entry, safe-area insets, the 900px split
manifest.webmanifest    not on disk yet; index.html links it
sw.js                   not on disk yet; app.js registers ./sw.js
.nojekyll               not on disk yet; required for deploy
NOTICE                  the licence text that ships
data/
  index.json            the manifest
  <key>.json            search rows
  <prefix>/<key>.json   a fat bucket split by a longer prefix
  entry/<key>.json      entry bodies
  ex/<key>.json         example sentences, by Tatoeba id
  forms/<key>.json      folded inflected form to its lemma
  LICENSE-DATA.md       the data licence, generated by the build
js/
  app.js                boot and the screen composition
  router.js             seven hash routes, one redirect
  data.js               the data contract and the fetch memo
  search.js             folding, ranking, the search pipeline
  storage.js            envelope, migrate, history and opened entries
  ui.js                 tab bar, Search, Entry, placeholder
tools/
  build-data.mjs        dev-only data build
  check-data.mjs        dev-only structural gate over data/
  data-exclusions.json  the copyright exclusion list
  sanity.mjs            dev-only Node checks over js/
```

Nothing under `tools/` ships and nothing under `tools/` is precached.

## The four layers

**1. The shell.** `index.html` holds one `#app` node, one `<script type="module" src="./js/app.js">`
and no other script. It sets `viewport-fit=cover`, so the CSS can read `env(safe-area-inset-*)`, and
it sets the Apple web-app meta tags and two `theme-color` values, light and dark. `styles.css` is the
only stylesheet. It owns the safe areas, the tab bar height, the 44px tap minimum and the two-pane
layout from 900px.

**2. The router.** `js/router.js` reads only the fragment, so the deploy subpath never reaches it.
Seven routes: `#/search`, `#/entry/<id>`, `#/text`, `#/reference`, `#/lists`, `#/study`,
`#/settings`. An empty fragment and `#/` mean Search. Anything else is replaced with `#/search`
through `location.replace()`, so Back leaves the app. The router owns screen lifetime: whatever
`render` returns is the screen's teardown, and it runs before the next render and on `stop()`.

**3. The data client.** `js/data.js` is the only module that names a file path or a JSON field. It
parses the manifest, picks the right file for a key, and keeps every loaded file in one memo.

**4. The screens.** `js/ui.js` draws the tab bar, the Search screen, the Entry screen and the
placeholder screen. `js/app.js` composes them: boot, the two-pane rule, and the route renderer. No
screen fetches. The app hands Search a `search(query)` function and Entry a promise, which is the
seam the Node checks use.

## Boot order

1. `app.js` reads the `#app` node. A missing node is a hard error.
2. It registers `./sw.js` with `{ updateViaCache: 'none' }`, fire-and-forget. A missing worker, an
   insecure context or a browser without one degrades to an ordinary online app. Boot never waits.
3. It opens the storage envelope: one key, one read, one `migrate()` walk.
4. It builds the data client and the search pipeline. Neither fetches anything yet.
5. It builds the tab bar and the Search screen once, and puts `main` above the bar. Both survive
   every later route change, so a query and its rows survive a trip into an entry and back.
6. It starts the router. The current route renders. On Search, the first draw reads the stored
   history, which is a local read.

The first `data/index.json` fetch happens on the first search of two characters or more, not at boot.
A boot fetch would delay the first screen for a file only a search needs.

A viewport crossing 900px re-renders the current route in place. It is not a navigation, so the
search screen keeps its field and rows.

## The data client contract

### Manifest

```
{
  version,        the build's id, a string
  built,          the source date, not the build time
  partial,        true when the build ran with a limit
  bucketKey,      the rule, as text, for a human
  sources: [{ url, licence }],
  totals: { entries, forms, examples, bytes },
  buckets: { "<key>": { search, entry, ex, forms } }
}
```

Each `search`, `entry`, `ex` and `forms` entry is an array of `{ path, bytes, hash }`. A broken bucket
is skipped and a missing count reads as `0`. The shell must open on a partial manifest, never fail.

`data/index.json` also carries the source licences, so the About screen can read them instead of
holding a copy. The full licence text ships in `NOTICE` and `data/LICENSE-DATA.md`.

### Buckets

A bucket key is the fold of the headword, first two letters or digits. Fold is NFD, drop the
combining marks, lowercase, then drop everything outside `a-z0-9`. A one-letter word keeps one
letter.

A bucket over 1 MB splits into files named by a longer prefix, for example `data/ca/cas.json`. The
client picks the file whose name-prefix is the longest one the key starts with. When no file prefix
matches, it reads the whole set. A bucket lookup falls back to the one-letter key.

### The four file sets

| Set | Holds | Shape |
|---|---|---|
| search | what a result row draws and what ranking matches | `[folded, id, headword, pronunciation, gloss, rank]` per row |
| entry | one entry body | `{ id, word, pos, cefr, ipa?, senses, ex, conj? }` |
| ex | the sentences of one bucket | `{ <tatoebaId>: "<sentence>" }` |
| forms | folded inflected form to its lemma | `{ <foldedForm>: { lemma, label } }` |

The entry body holds example ids, never example text. That is what keeps the CC BY 2.0 FR sentences
out of the CC BY-SA shards. See ADR 0001.

`toRow`, `toEntry`, `parseForms` and `parseExamples` also read the named shapes, so a build change
from a compact array to a named object does not break the app.

### Which fetch each screen triggers

| Action | Files fetched |
|---|---|
| boot | none |
| first search of 2+ characters | `data/index.json`, then the row file of the query's bucket |
| a search with a short result list | the forms file of that bucket, then the row file of the lemma's bucket when a form hits |
| opening an entry from a row | the entry file of the row's bucket, then the ex file of that bucket |
| a reload of `#/entry/<id>` | the entry file of the stored bucket, then its ex file |
| a reload of an entry id this build never opened | none; one honest line replaces the sections |
| any tab screen | none |
| a history tap | none; the query runs, so the row file does |

### The memo and the `?v=` rule

Every file is fetched at most once per session. The promise is kept, so a keystroke after the first
costs no request and an entry opened twice costs one. A failed load is dropped from the memo, so a
retry can succeed.

The manifest carries a per-file `hash`, and the client does not use it: it requests `path` with no
query string. A cache-safe rule exists and is not built: request `path + '?v=' + hash`, so a rebuilt
file is a new URL and a cached one never revalidates. Today freshness depends on the service worker's
cache names alone.

The memo has no bound and no eviction. A long session that walks many buckets keeps every file it
touched. That is the whole set in the worst case, which is the size of the download.

## Storage

```
localStorage['itadict'] = { v: 1, data: { history: [...], opened: [{ id, bucket }] } }
```

- `history` holds the last 50 queries, newest first, trimmed and de-duplicated.
- `opened` holds the last 200 entry ids with the bucket their body came from. An id cannot be turned
  back into a bucket, so this is the only way a reload of `#/entry/<id>` finds its body.
- One key, one envelope, one `migrate(v, data)` walk. The step table is empty because `v: 1` is the
  first shipped envelope. A bump is one step plus the constant.
- Unknown top-level keys survive every read and every write. Nothing is pruned.
- A blob this build cannot read, or one written by a newer build, is left byte-for-byte alone and
  every write is refused. The app keeps working from memory for the session.
- A failed `setItem` (quota, private mode) flips the session to memory-only and never throws.

Notes, lists and study progress are not in the envelope yet. Their milestone adds them under their own
keys inside `data`.

## Service worker

`sw.js` is one hand-written classic worker at the root of the subpath. ADR 0003 is the authority; the
table is the contract.

| Request | Strategy | Why |
|---|---|---|
| shell | precached on install, cache-first | an installed app must open with no network |
| navigations | the cached `./index.html`, network fallback | never a browser error page |
| app code (`js/**`, `sw.js`, CSS, the manifest) | network-first, cache fallback | a fix lands on the first online load |
| content files (`data/**`, except the manifest) | cache-first, cached forever | a content file never changes contents |
| `data/index.json` | stale-while-revalidate | a new file list arrives on the next load |

Two caches: the shell cache is dropped on every deploy, the data cache is not. App code is matched
before the shell, so `styles.css` and the manifest are precached and also network-first.

Status: not on disk yet. The registration call is in place, so the worker ships without touching
`index.html` or `app.js`.

## Deploy

The site is `https://maxarturo.github.io/itadict/`. The subpath is `/itadict/` and it is frozen.

1. **Every URL is relative.** `./js/app.js`, `./data/index.json`. An absolute path works on a root
   dev server and 404s on Pages.
2. **`.nojekyll` at the root.** Otherwise Jekyll drops a file that begins with an underscore.
3. **`sw.js` answers 200 at `/itadict/sw.js`.** A missing worker means no offline, with no visible
   error.
4. **`CACHE` is bumped on every deploy.** Pages sends `Cache-Control: max-age=600`, so `sw.js` itself
   can be ten minutes stale. A bump is the only way a fix reaches an installed app.
5. **The first load is online.** An install that never loaded online has nothing cached.

To test the deployed shape locally, serve the parent directory so the subpath is real:

```
cd /home/max/Developer && python3 -m http.server 8000
# then open http://localhost:8000/itadict/
```

`file://` has no secure context, so the worker never registers there.

## What a test can prove, and what it cannot

Node, `npm test`, proves:

- the fold, the bucket key, and the mapped offsets of a highlighted match;
- ranking order, the tie rules, the result cap, and the fuzzy budget;
- a one-character query reads history and fetches nothing;
- an inflected form resolves to its lemma, including a lemma in another bucket;
- the router parses exactly seven routes, repairs a bad fragment in place, renders once per route and
  tears a screen down;
- the envelope migrates forward, keeps unknown keys, caps both lists, refuses a newer or broken blob;
- the manifest parses into four file sets per bucket and skips a broken one;
- the file for a key is the longest prefix match;
- the client reads the shapes the build writes, and fetches one file per lookup.

`npm run check` proves the data: the manifest matches the files, the byte counts and the hashes, the
size caps hold, every form points at a shipped lemma, every example id has a sentence, no entry ships
sentence text, no excluded headword ships, and the licence lines are present.

A browser is needed for layout, the 900px split, focus order, the tab bar hit areas, the safe-area
insets, and whether a tap lands. A device is needed for the home-screen install, the real safe areas,
TTS voices, the real swipe, and eviction under memory pressure. Those are the gate-2 rows.

## Gaps between the code and the ADRs

Recorded on purpose. Fix the code or the ADR; do not let the two drift.

1. `sw.js`, `manifest.webmanifest` and `.nojekyll` are not on disk. `index.html` links the manifest
   and `app.js` registers the worker, so both answer 404 today.
2. A search row is six fields, `[folded, id, headword, pronunciation, gloss, rank]`, plus an optional
   `matched` on the row object. ADR 0004 says five.
3. The forms set maps a form to `{ lemma, label }`, and `lemma` is a headword, not an id. ADR 0004
   says `[id, headword]`.
4. The `?v=<hash>` rule is decided and not built. The manifest hash is unused.
5. There is no LRU. The memo grows for the session.
6. Boot does not fetch the manifest. The first search does.
